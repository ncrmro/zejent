# REQ-012 — Portable runtimes and macOS hosts

The image **MUST** be a standard OCI/docker-archive artifact for `aarch64-linux` and `x86_64-linux` so it loads unmodified into any conformant runtime (Podman, Docker, containerd/k8s, Apple Containerization). Launcher scripts (`build-image.sh`, `run-image.sh`) **MUST** run on both GNU/Linux and macOS/BSD userlands; they **MUST NOT** depend on GNU-only flag forms of `sed`, `xargs`, or `readlink` beyond what macOS provides. The flake **MUST** expose `packages.<darwin-system>.image` aliases of the matching Linux package set so `nix build .#image` resolves on macOS hosts and dispatches to a configured Linux builder; documentation **SHOULD** state that macOS users without a Linux builder can pull the published `ghcr.io/ncrmro/zejent` image instead of building locally. On macOS, the primary supported runtime is Podman with a `podman machine` VM that mounts `/Users`, preserving REQ-005 identical-path workspace mounts. Zejent **SHOULD** additionally support Apple's Containerization framework (`container` CLI, macOS 26+) as a runtime: the image already loads there, but the launcher's Podman-specific surface (`play kube` pods, Podman secrets, `podman exec` attach) needs an alternate code path (`container run` with volume/env equivalents) before attach-or-create (REQ-004) works; that launcher work is **OPTIONAL** until the `container` CLI stabilizes. Runtime support beyond Podman **MUST NOT** weaken REQ-009 credential handling (no raw tokens in rendered launch specs).
