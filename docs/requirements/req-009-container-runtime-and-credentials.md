# REQ-009 — Container runtime and credentials

The image **MUST** provide a working `HOME`, writable `/tmp`, required CA certificate environment variables, and shell configuration that avoids recursive `/etc/zshenv` loading. The generated Kubernetes YAML **MUST** mount `/tmp` from a persistent per-workspace volume so Outfitter/Pi temporary state and Zellij runtime files can survive container recreation where possible. The image **MUST** include `gh`, and `gh` plus Git HTTPS operations **MUST** authenticate from a mounted GitHub-token Podman secret when available. If the GitHub token secret is missing, the interactive launcher **MUST** show a GitHub token creation URL, required permissions, and a silent paste prompt. The rendered pod YAML **MUST NOT** contain raw GitHub token values. The launcher **MUST NOT** pass `OPENAI_API_KEY` for Pi auth. The host `${PI_HOME_DIR:-$HOME/.pi}` **MUST** be mounted read-only at `/root/.pi` so existing host credentials are visible without copying secrets into Podman volumes. Zejent **MUST NOT** make host Pi credentials writable inside the container. Writable Pi runtime/session state **MUST** live in a persistent container path, such as `/tmp/pi-sessions` backed by the persistent `/tmp` volume. Zejent **SHOULD** persist writable Outfitter/Pi runtime and cache state across detach, reattach, and pod recreation so setup does not rerun unnecessarily. Zejent **SHOULD** store writable Pi/Outfitter state in Zejent-owned persistent storage separate from read-only host credentials. Any persistence change **MUST NOT** reintroduce Pi/Outfitter `EROFS` failures against `/root/.pi`. The `leader-agent` tab **MUST** start `outfitter run --profile zejent -- --session-id <stable-id> --name <display-name>` by default. The Zejent profile **MUST** inject the repository-owned system prompt through Outfitter profile controls.
